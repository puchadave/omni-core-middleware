# Admin Deployment Guide

## Scope

This guide covers deployment of the existing FastAPI/Jinja2 administrative application. It does not introduce a second backend architecture.

## Runtime Stack

- Python 3.11
- FastAPI and Uvicorn
- Jinja2 templates
- PostgreSQL 15 through `asyncpg`
- SQLite WAL fallback through `aiosqlite` when `DATABASE_URL` is absent
- In-memory `asyncio.Queue` for short background jobs
- Optional OmniRoute, Matterhorn, Shopware and Google integrations

## Prerequisites

- Docker Engine 20.10+ and Docker Compose v2, or a compatible Python runtime.
- Outbound access for configured external integrations.
- Persistent storage for PostgreSQL and `/app/data`.
- A reverse proxy with TLS termination for production.

## Environment

Copy `.env.example` only when overrides are required. The important variables are:

```dotenv
POSTGRES_USER=omnicore
POSTGRES_PASSWORD=<long-random-secret>
POSTGRES_DB=omnicore
OMNI_CORE_PORT=8000
DATABASE_URL=
OMNIROUTE_URL=
OMNIROUTE_API_KEY=
MATTERHORN_API_TOKEN=
INTERNAL_API_KEY=<long-random-secret>
SESSION_SECRET=<long-random-secret>
```

`start.sh` generates a random PostgreSQL password when `.env` is absent. Add `INTERNAL_API_KEY` and `SESSION_SECRET` explicitly for any environment that exposes the admin UI.

Never commit `.env`, private keys, tokens or credentials.

## Docker Deployment

From the repository root:

```sh
chmod +x start.sh
./start.sh
```

Or run Compose directly:

```sh
docker compose up --build -d --remove-orphans
```

Relevant services:

- `db`: PostgreSQL 15 Alpine with persistent `pg_data` volume and health check.
- `omni-core`: FastAPI/Uvicorn/uvloop service on port 8000 with persistent `app_data` volume and `/api/health` health check.

Check status:

```sh
docker compose ps
curl http://localhost:8000/api/health
docker compose logs -f omni-core
```

Stop without deleting data:

```sh
docker compose down
```

Destructive reset:

```sh
docker compose down -v
```

## Native/Development Deployment

```sh
python -m pip install -r requirements.txt
export DATABASE_URL=postgresql://omnicore:<password>@localhost:5432/omnicore
export INTERNAL_API_KEY=<long-random-secret>
export SESSION_SECRET=<long-random-secret>
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
```

Without `DATABASE_URL`, the application uses SQLite WAL. This is suitable for local development and small installations, not as a replacement for PostgreSQL in production.

## Startup and Migration

The application initializes the configured database during startup. Startup retries PostgreSQL connection establishment for up to 60 seconds. Existing database initialization is in `database.py`; no separate database migration command was added by this admin implementation.

## Production Hardening

- Put the service behind a reverse proxy and enable HTTPS.
- Set a unique strong `POSTGRES_PASSWORD`, `INTERNAL_API_KEY` and `SESSION_SECRET`.
- Do not publish the database port publicly.
- Restrict Docker/API access to trusted networks.
- Back up PostgreSQL and `/app/data` regularly.
- Add monitoring, alerting, log retention and a rollback procedure.
- Replace the in-memory queue with a durable queue if jobs must survive restarts.
- Complete the multi-user RBAC, CSRF, rate limiting and audit requirements before exposing the admin UI beyond a trusted network.
- Keep placeholder integrations clearly marked as not configured.

## Important Deployment Caveats

- `INTERNAL_API_KEY` and `SESSION_SECRET` are not generated by `start.sh`.
- The existing `deploy_omni_docker.sh` references container names that do not exactly match `docker-compose.yml`; use `docker-compose.yml`/`start.sh` as the authoritative path.
- The application is intentionally single-worker because runtime state and the queue are in-memory.
- No CI/CD pipeline, production monitoring stack, TLS configuration or backup automation is defined in the repository.
